# Nestify

<p align="center">
  <img src="./Nestify.png" alt="Nestify Logo" width="180" />
</p>

Nestify 是一个面向 NAS / 家庭服务器场景的可视化文件整理与规则执行平台，当前已具备完整的前后端界面、SQLite 持久化、规则管理、任务日志、目录浏览、系统设置、规则备份恢复、手动文件管理与基础自动化执行能力。

## 主要能力

- 单管理员登录与会话管理
- 仪表盘概览：
  - 总规则数
  - 今日处理量
  - 运行中任务
  - 最近执行摘要
  - 系统资源占用
- 规则管理：
  - 归档规则
    - 打包归档
    - 收集归档
    - 匹配归档：按关键词或扩展名直接分流文件到目标目录，不参与打包
    - 单件归巢：命中裸露文件后自动创建同名目录并转移
    - 嵌套打包 / 扁平归档 / 清理源文件 / 归档校验等模块化开关
  - 净化规则
    - 清理空文件夹
    - 按文件名匹配规则清理文件
    - 繁转简
    - 匹配转换（按自定义规则重命名文件或文件夹）
    - 匹配过滤：仅对文件夹名称命中的片段执行清除，不删除文件夹本体
  - 链路规则
    - 软链模式
    - 硬链模式
    - Strm 模式：按扩展名生成播放列表文件
    - 文件名黑名单，一行一条，命中即跳过创建链路
  - 命名规则
    - 使用命名规则集批量处理文件名和文件夹名
    - 可分别选择包含文件、包含文件夹，默认均不勾选
    - 支持实时监听、计划执行和手动执行
  - 规则列表增强
    - 归巢历史支持按文件名 / 修改时间正序倒序排序
    - 归巢历史支持按成功 / 失败 / 跳过筛选
    - 运行历史支持按规则项目筛选（归档 / 净化 / 链路 / 命名）
    - 归巢历史支持显示模式列，并按模式展示对应颜色标签
    - 所有规则支持右键复制规则
    - 净化规则列表移除目标路径列，仅展示监控目录
    - 链路规则模式列精简为“硬链 / 软链”展示
- 目录选择器：
  - 支持系统根目录浏览
  - 支持手动输入路径
  - 默认直接展示根目录下一层子目录
- 手动整理：支持浏览目录并对条目进行手动打包
- 任务日志与运行历史
- 文件管理：
  - 目录面包屑导航
  - 最近访问目录
  - 文件/目录排序
  - 新建文件夹
  - 上传、复制、移动、重命名、删除
  - 归档文件解压
  - 目录收藏
  - 手动预检
- 系统设置：
  - 日志保留天数
  - 最大日志条数
  - 管理员账号修改
  - 规则导出备份 / 导入恢复

## 当前规则说明

### 1. 归档规则

支持两种模式：

- `package`：按卷或目录打包归档
- `collect`：收集文件到目标目录

支持：

- 实时监听执行
- 定时执行
- 启动后立即执行
- 本地模式 / 兼容模式
- 文件名匹配黑名单：命中后跳过归档处理
- 打包归档附加模块：
  - 扁平归档
  - 归档清单
  - 归档校验
  - 清理源文件
  - 嵌套打包
  - 匹配归档：
    - 仅在打包归档模式生效
    - 一行一条规则
    - 支持按扩展名匹配，例如 `mp4`
    - 支持按关键词匹配，例如 `cover`
    - 扩展名匹配保持大小写不敏感
    - 命中的文件直接转移到目标路径对应目录，不参与 CBZ 打包
    - 支持父级目录重名：
      - 监控目录根下的裸露命中文件不做父级重名
      - 多层子目录中的命中文件统一按监控目录下第一层父目录命名
      - 多个同父级命中项依次追加 `-part1`、`-part2` 等后缀
    - 图片集打包为 CBZ 时，勾选父级目录重名后也会统一按监控目录下第一层父目录命名，并在重名时自动追加 `-part(n)` 后缀
- 单件归巢：
  - 仅在打包归档模式生效
  - 只处理监控目录根下的裸露文件
  - 一行一条规则
  - 支持关键词、扩展名或正则匹配文件名
  - 命中后自动整理为 `目标目录/文件主名/原文件名`
- 收集归档附加模块：
  - 递归收集
  - 同名去重（模式内固定启用；同内容跳过，异内容首个追加 `-re`，后续跨扩展名依次追加 `-re1`、`-re2`）
  - 清理源文件（关闭后改为保留源文件）

### 2. 净化规则

用于清理与转换监控目录下的内容，支持两类模式：

- `cleanup`：
  - 清理空文件夹
  - 按文件名规则清理文件
  - 空文件夹清理白名单：一行一个文件夹全称，仅跳过当前层空目录删除，子目录仍按规则继续清理
  - `transform`：
    - 繁体中文转换为简体中文
    - 按自定义规则批量重命名文件和文件夹
    - 匹配过滤：一行一个，仅在文件夹重命名时生效；命中后从文件夹名称中清除对应片段

进一步修正了打包归档中的父级重名与分卷命名逻辑：多子文件夹打包为 CBZ 时从首个文件起即按 `-part(number)` 编号；匹配归档命中的文件在勾选父级重名后，会按监控目录下第一层父级正确重命名，并过滤异常路径片段。打包模式与收集模式中的同名去重现已统一为模式固有能力，不再作为单独功能卡片展示。

文件名规则为一行一条，可写普通文本或正则表达式。转换规则支持自定义文本匹配与替换。

### 3. 链路规则

链路规则已并入“规则管理”页面，与净化规则同级展示。

支持：

- 软链模式
- 硬链模式
- Strm 模式：递归扫描监控目录，按扩展名生成对应的 `.strm` 文件
- 自定义监控目录
- 自定义链路目录
- 实时监听新文件出现后自动创建链路
- 计划执行全量创建链路
- Strm 模式支持增量同步与全量同步，并可清理目标目录中的旧 `.strm` 文件
- 文件名黑名单：
  - 一行一条
  - 支持文本或正则
  - 仅匹配文件名
  - 命中后跳过创建链路

默认开启计划执行时，Cron 表达式为：

```text
30 4 * * *
```

即每天 `04:30` 执行一次。

### 4. 命名规则

命名规则使用命名规则集对监控目录根下的条目执行批量重命名，可通过实时监听、计划执行或手动执行触发。

新增命名规则时，可在“应用范围”功能卡片中独立选择：

- **包含文件夹**：处理监控目录根下的文件夹。
- **包含文件**：处理监控目录根下的文件。
- 两项同时勾选：同时处理文件夹和文件。
- 两项默认均不勾选：不处理任何条目，避免创建规则后意外改名。

命名规则集支持按规则顺序执行文本替换、正则替换、大小写转换、前后缀处理及序号补齐等命名操作；序号只对实际纳入应用范围的条目递增。

## 日志保留策略

系统设置页已支持日志保留策略保存。

默认值：

- 日志保留天数：`5`
- 最大日志条数：`10000`

运行历史在写入时会自动应用保留策略：

- 超过保留天数的历史记录自动清理
- 超过最大条数时，仅保留最新的记录

## 本地开发

### 启动后端

```bash
cd backend
go run ./cmd/server
```

默认监听：

```text
:8080
```

### 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端开发服务器默认监听 `5173`，并将 `/api` 请求代理到后端。

### 构建检查

后端：

```bash
cd backend
go build ./...
```

前端：

```bash
cd frontend
npm run build
```

## 环境变量

可通过环境变量覆盖运行配置：

- `NESTIFY_HTTP_ADDR`
- `NESTIFY_WEB_DIR`
- `NESTIFY_DB_PATH`
- `NESTIFY_ADMIN_INITIAL_USERNAME`
- `NESTIFY_ADMIN_INITIAL_PASSWORD`
- `NESTIFY_BROWSE_ROOTS`

## 默认管理员初始化

首次启动且数据库中不存在管理员账号时，会自动创建管理员：

- 用户名默认值：`admin`
- 密码默认值：`nestify123`

建议生产环境覆盖：

```bash
NESTIFY_ADMIN_INITIAL_USERNAME=your-admin
NESTIFY_ADMIN_INITIAL_PASSWORD=your-strong-password
```

## 路径浏览根目录

路径选择器默认自动推断可浏览根目录：

- Windows：自动推断可用盘符
- Linux / 容器：默认使用根目录 `/`

如需限制前端只能浏览指定目录，可设置：

```bash
NESTIFY_BROWSE_ROOTS=/library;/archive;/config
```

多个根目录使用分号分隔。

## 容器运行

```bash
docker compose up --build
```

容器模式下：

- 前端构建产物由后端从 `/app/web` 托管
- 默认访问地址：`http://localhost:8080`

### Docker Compose 部署示例

```yaml
services:
  nestify:
    image: ghcr.io/hyaeve/nestify:latest
    container_name: Nestify
    network_mode: bridge
    ports:
      - 8080:8080
    volumes:
      - ./config:/config
      - ./data:/data
      - ./logs:/logs
    environment:
      NESTIFY_HTTP_ADDR: ":8080"
      NESTIFY_CONFIG_PATH: "/config/config.yaml"
      NESTIFY_WEB_DIR: "/app/web"
      NESTIFY_DB_PATH: "/data/app.db"
      NESTIFY_ADMIN_INITIAL_USERNAME: "admin"
      NESTIFY_ADMIN_INITIAL_PASSWORD: "password"
    restart: always
```

说明：

- 将配置文件放置到宿主机 [`config/config.yaml`](config/config.example.yaml)
- 首次启动前建议修改默认管理员账号与密码
- 持久化目录建议保留 [`./data`](data/) 与 [`./logs`](logs/)

## GitHub 自动构建镜像

仓库已包含工作流 [`docker-image.yml`](.github/workflows/docker-image.yml)，可在推送到 GitHub 后自动构建容器镜像。

### 触发方式

- 推送到 `main` / `master`
- 推送标签 `v*`
- 手动触发 GitHub Actions
- Pull Request 时执行构建验证但不推送镜像

### 镜像仓库

默认推送到 GitHub Container Registry：

```text
ghcr.io/<owner>/<repo>
```

### 自动标签

- `latest`
- 分支名标签
- Git 标签
- 提交 SHA 标签
