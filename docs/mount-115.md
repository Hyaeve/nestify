# 115 远程挂载

系统设置 → 远程挂载 → 添加挂载，选择「115 网盘」。

## 登录与配置

- **CK**：填写含 `UID`、`CID`、`SEID` 的 Cookie；有 `KID` 时一并保留。选择该 CK 对应的设备类型。
- **扫码**：先选择设备，再获取二维码并在 115 客户端确认。成功后 CK 自动回填，点击「确认」才保存挂载。
- **API 请求间隔**：单位毫秒，默认 1000，可设置 0–60000。0 表示不主动增加等待。
  同一账号在本进程中的挂载和工作线程共用限速状态，列目录的每一页也计入请求间隔。
  执行器另有请求间隔时使用较大的值。扫码状态轮询最少间隔 2 秒。
- **指定路径**：填写网盘内路径，例如 `/影视`；留空为网盘根目录，不填写 WebDAV 的 `/dav`。
- **测试**：读取指定路径，确认账号凭据和目录可用，不修改网盘内容。

设备选项即 115 官方客户端清单（115生活 / 115 / 115管理，共 16 项），取值同时是扫码接口的 app 段：
网页端 `web`、`ios`、`115ios`、`android`、`115android`、`ipad`、`115ipad`、`qandroid`、`qios`、`qipad`、
`os_windows`、`os_mac`、`os_linux`、`wechatmini`、`alipaymini`、`harmony`。
扫码按选中的设备换取 CK；更换下拉选项不会把已有 CK 转换成另一设备的 CK。
苹果系设备（含 `115ios`、`ipad`、`115ipad`、`qios`、`qipad`）使用 iOS 客户端 UA，
其余设备沿用默认 UA。旧配置里存过的 `tv`（电视端）仍可保存和运行，但已不在下拉中。

## 当前支持范围

- 创建、编辑、启停和删除挂载配置；删除配置不会删除网盘文件。
- 文件管理、目录选择器中的逐层浏览与分页目录列举。
- 通过现有远程净化执行器执行已配置的清理操作。删除目录前确认目录为空，拒绝删除挂载根，
  目录内有重名路径时拒绝猜测目标。
- 远程客户端的读取、存在性检查和文件下载能力。

暂不支持通过原生 115 挂载上传文件、创建目录、作为备份目标或生成 STRM。
这些操作返回明确错误，不会误发 WebDAV 请求。STRM 仍可使用现有 OpenList 挂载。
115 的临时下载地址不作为持久播放地址写入 STRM。

## 凭据与兼容性

CK 与已有挂载密码采用同样的本地数据库存储方式，**在配置数据库中为明文**，请保护 `data/app.db`
及其备份。列表、创建和更新响应仅返回 `has_cookie`，不返回 CK；已登录管理员的单条编辑接口
才返回 CK，并设置 `Cache-Control: no-store`。SDK 原始错误不直接回传，避免泄露凭据或扫码参数。
扫码会话绑定当前管理员登录会话，最多有效 5 分钟；二维码在服务端本地生成，不发送给第三方二维码服务。

继续使用 `webdav://<挂载ID>/...` 作为内部虚拟路径，实际协议由 `provider=115` 分流。
既有 WebDAV/OpenList 挂载、规则中的路径和挂载编号不改变。旧库自动补齐
`cookie`、`device`、`request_interval_ms` 三列。

Go 接入依赖固定为 `github.com/SheltonZhu/115driver v1.3.5`，构建要求 Go 1.23 及以上。
Docker 构建阶段和运行镜像的 CA 证书配置已同步。

部署代码更新后执行：

```sh
docker compose up -d --build
```

自动化测试使用模拟 115 响应，不使用真实账号；真实 CK 有效性和扫码登录须在部署后进行连接测试。
